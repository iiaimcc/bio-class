**方式 A（推荐，课上现场下载）**：在课程包根目录执行


下载总量约 128 MB（30 个文件），本机实测首次约 13 分钟，机房带宽差时更久——所以课上默认指向共享缓存（见方式 A-），只有网络空闲时才建议直连。脚本每次都会打印 5 个输出文件的 SHA256，可与 `data/README.md` 的发布版校验值比对。


**方式 B（兜底，网络不可用）**：直接用老师共享的 `materials/fallback/inputs/`（同一份数据，已压缩，含 SHA256）。解压到工作目录即可，后续步骤完全一样。

## 第 1 步：差异表达分析（40 分钟）

### 1.1 认识数据（8 分钟）

在 RStudio 左上角控制台输入：

```r
counts <- read.csv("expression_matrix.csv", row.names = 1, check.names = FALSE)
dim(counts)            # 60660 行 × 30 列
colSums(counts) / 1e6  # 每个样本的总 reads（百万）——观察：一样吗？
meta <- read.csv("sample_meta.csv")
table(meta$condition)  # Normal 15 / Tumor 15
```

**预期结果**：30 个样本的库深度在 2300 万到 8500 万 reads 之间，**差别很大**。想想为什么不能直接拿两个样本的数值相减（思考题①）。

打开脚本 `01_diff_analysis.R`（Files 面板进入 `scripts/` 子目录点击选中 → Open），然后用终端运行：

## 第 3 步：靶点初筛与突变证据（40 分钟；其中查库部分可与第 2 步的脚本运行并行）

1. **先标注变异功能（10 分钟，最好在第 2 步跑富集的等待时间里就开始）**：先让脚本把逐变异的表骨架生成出来，再逐条查库：

```bash
python3 ../data/make_variant_template.py ../data ./results/variant_calls.csv   # 27 行，4 条截短变异已自动填好
python3 ../data/lookup_variant.py EGFR p.L858R          # 查 ClinVar + CIViC，只给记录，不给结论
python3 ../data/lookup_variant.py PIK3CA p.P104L
```

**截短变异（无义/移码）不用查**——蛋白被打坏了，不可能"打开"，脚本已把这一类自动判为功能缺失（**判的是这一条变异，不是整个基因**：同一个基因里的错义变异仍然要逐条查库，例如 TP53 有 4 条错义变异查库后判为功能受损、4 条仍为未明）；**剪接位点、起始密码子、非终止变异也不自动判**（效应取决于转录本与阅读框，或者根本不是截短），本队列没有这类变异。剩下 23 行是错义变异与框内缺失，要你把 `needs_review` 改成 `gain_of_function` / `loss_of_function` / `uncertain`，并补上 `evidence_level` 与 `evidence_source`（能被人打开核对），填法见 `materials/templates/README.md`。填完再跑下一步。

2. 运行脚本 `03_target_shortlist.R`（第三个参数是变异功能表，省略时读结果目录里的 `variant_calls.csv`）：

```bash
Rscript scripts/03_target_shortlist.R  .  ./results
```

3. 脚本做三件事，对应四份输出：
   - **表达驱动的候选**：7283 个 DEG 与可成药面板（实测 247 个基因）求交集，按 log2FC 排序 → `target_shortlist.csv`，实测 **78 个**候选，top5 为 TERT、HTR3A、TOP2A、CDKN2A、SLC6A3；
   - **突变驱动的候选**：读 `mutation_matrix.csv`，列出有非沉默突变的基因 → `mutation_driven_candidates.csv`；再打一份 `mutation_status.csv` 给课外查阅；
   - **三层证据综合（只用肿瘤与分子的事实）**：把突变基因依次过"变异把蛋白打开了吗（功能获得）→ 我们要做的大分子够得着吗（定位）"两道筛子，写 `integrated_candidates.csv`（每一层砍掉谁都留着）与 `target_recommendation.csv`（三层全过的结果）。第二层的截短变异由脚本自动判、错义变异读你填的表；定位由 `data/annotate_targets.py` 从 UniProt 自动标注（能自动的不人工维护）。控制台会打印漏斗、第二层的判定明细与两个对照：

```

  2. + variant switches the protein ON  : 3 genes
  3. + reachable by a large molecule    : 1 gene(s)

---- Layer 2 how each gene was settled (variant calls rolled up) ----
symbol  n_variants  n_gof  n_lof  n_uncertain  variant_function
TP53             9      0      5            4  loss_of_function
KRAS             6      6      0            0  gain_of_function
...

---- Not part of the funnel: what the same data looks like for the other modality ----
Switched-on AND intracellular (= small-molecule route): KRAS, PIK3CA
```
4. **预期结果（两个关键观察）**：
   - **综合推荐只有一个：EGFR（rank 1）**。它出现在突变表里——14 例有突变数据的肿瘤中有 2 例携带 EGFR 激活突变（第 15 例没有 WXS 文件，按未知处理）：

```

EGFR            2 p.E746_A750del; p.L858R not significant         -0.206   0.564
```

一例是外显子 19 缺失（E746_A750del），一例是 L858R，都是教科书级的 EGFR 激活突变，而且正是 EGFR-TKI 针对的变异类型——这两条也是你自己查库填进 `variant_calls.csv` 的（CIViC 的敏感度证据 level A/C、ClinVar 的药物反应记录、Lynch 2004 / Paez 2004）。表达没变、突变有变，这就是它进入靶点名单的理由。

   - **78 个表达候选与这条漏斗的交集是 0**。两条路测的是不同证据：表达候选仍需要进一步验证。TP53、STK11、KEAP1 均检出功能缺失变异，但必须逐条判读，不能把同一基因的所有变异归为一类：

     | 基因 | 截短变异自动判 LOF | 错义变异查库判功能受损 | 意义未明 |
     |---|---:|---:|---:|
     | TP53 | 1 | 4 | 4 |
     | STK11 | 2 | 0 | 1 |
     | KEAP1 | 1 | 0 | 1 |

5. 打开五份输出，完成：
   - 写出 `target_shortlist.csv` 实测 top5，不要凭印象填写（这些是表达驱动的候选，需要各自补证据）；
   - 看 `known_drug_class` 列确认这些候选是否已有在研/在用药（`panel_class` 只是面板维护者的粗分类，别拿它下生物学结论）；`drug_precedent.csv` 里的药物格局同样只作事后参考，不进漏斗；
   - 列出突变表里除 EGFR 外还有哪些基因、各几例（实测 TP53 8 例、KRAS 6 例、STK11 3 例、RET 2 例、KEAP1 2 例、SMARCA4 / PIK3CA / ROS1 各 1 例）；
   - 在记录表里写下漏斗每一层的基因数，并说明候选未进入下一层的依据；分清截短变异自动判定、其余变异逐条查库，以及胞外可达性的判断，不按基因名自动定性；
   - **把 PIK3CA P104L 的证据写清楚**：ClinVar 判它致病，但语境是生殖系过度生长综合征（由 PIK3CA 功能获得驱动）、不是体细胞热点；照实写 `gain_of_function` / `moderate` 并注明语境——这就是"证据分级"的练习；
   - **填一张"判据 vs 佐证"表**（模板与参考答案见 `docs/文献依据.md` 第 1 节）：对 9 个突变候选逐一标出①突变有无②变异功能（功能获得/缺失/未明）③定位④是否匹配课程三的大分子模态——这四栏是**判据**；再另起两栏写"是否有上市药""有哪些文献"，并在表头注明这两栏**只作事后佐证、不参与筛选**。填完你会发现按判据留下的只有 EGFR；同一份数据改做小分子，候选为 KRAS 与 PIK3CA，后者须保留生殖系证据语境的说明。

**靶点初筛结论模板**（课后报告的第一版结论）：

> 在真实 TCGA-LUAD 子集（15 肿瘤 vs 15 癌旁）中，7283 个基因满足 padj<0.05 且 |log2FC|>1，与可成药面板交集得到 78 个表达驱动的候选（top: TERT、HTR3A、TOP2A）。EGFR 不在其中：其 mRNA 在肿瘤与癌旁间无显著差异（log2FC≈-0.21，padj≈0.56）。改从突变出发，只用肿瘤与分子自身的事实做筛子——是否有非沉默突变、变异是否把蛋白打开（功能获得）、蛋白是否在课程三要设计的大分子够得着的位置——漏斗为 9 → 3 → 1，只剩 EGFR：14 例有突变数据的肿瘤中 2 例携带其激活突变（E746_A750del、L858R），受体有胞外域。注意 78 个表达候选与这条漏斗没有任何重叠：表达层是无假设扫描，产物是"待做依赖实验的候选池"；漏斗挑的是"验证成本最低"的那一个，两者是广度与成本的取舍，不是对错关系。同一条链路上，KRAS（6 例）与 PIK3CA（P104L）同样功能获得但位于胞内，若课程三改做小分子就是它们留下来的——**所以结论应表述为"按大分子路线，EGFR 是本批数据里最站得住的那个"，而不是"EGFR 是最好的靶点"**。药物上市情况与文献可得性只作事后佐证，不能当筛选条件（否则是把已知答案当证据）。反证：14 例有突变数据的肿瘤中检出率仅 2/14（第 15 例无 MAF），且突变阳性不等于肿瘤依赖该通路，仍需蛋白水平、功能干预与临床数据佐证。

> 卡住了？①交集后候选数为 0：多为基因名格式不一致（引号/空格），或第一个参数没有指向 `data/`。②`mutation_matrix.csv` 找不到：说明没跑第 0 步的脚本，也没解压兜底数据。③只有 14 例肿瘤有突变数据：TCGA-05-4245 没有 WXS 文件，**没有突变记录不等于野生型**，这是真实数据里常见的数据缺失。

### 5.2 从 DEG 到药靶的证据链（10 分钟）

以 EGFR 为例，各写一条：

1. 表达证据：**阴性**——padj≈0.56，表达未随肿瘤变化（要如实写出来）；
2. 突变证据：14 例有突变数据的肿瘤中 2 例携带激活突变（19del、L858R），功能获得由查库确认（CIViC 敏感度证据、ClinVar 药物反应记录、Lynch 2004 / Paez 2004），变异类型正是获批药针对的类型；
3. 定位证据：受体酪氨酸激酶、有胞外域（`target_context.csv` 由 UniProt 自动标注），大分子够得着；已有获批抗体与 TKI；
4. 因果缺口：突变不等于通路依赖，样本量小，未见功能实验；
5. 反证：突变阴性的大多数肿瘤、EGFR 表达无差异，都会降低“广谱依赖”的说法；KRAS 与 PIK3CA 同样功能获得，说明"这批数据里 EGFR 唯一"只在**大分子模态**下成立；
6. 下一步：蛋白/结构层面验证（课程二）、界面与设计层面（课程三）。
