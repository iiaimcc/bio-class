# 第一学时：count 到底是什么东西

## 先看这张表本身

在 RStudio 里敲这三行：

```r
counts <- read.csv("expression_matrix.csv", row.names = 1, check.names = FALSE)
dim(counts)
head(counts[, 1:4], 3)
```

`dim` 会告诉你 60660 和 30。前几行长这样：基因 ID 在前面，后面跟着几列整数。

这个"整数"很重要。

RNA-seq 做的事情，简单说就是：把样本里的 RNA 提出来、逆转录成 cDNA、建库、上机测序。测序仪吐出来一堆短序列，叫 reads。这些 reads 经过质控和比对，被分配到各个基因头上。

所以某个基因在某个样本里的 count，就是"这次测序里，有多少条 reads 落到了这个基因上"。

注意这句话的措辞：是 reads 条数，不是分子个数，不是浓度。

很多同学第一遍读不出区别。等做到第三步就知道厉害了——两个样本测的 reads 总数都不一样，你拿条数直接比，比的是什么？

再敲一行：

```r
colSums(counts) / 1e6
```

30 个数，从 2300 万到 8500 万 reads 都有。

看出来了吗？差了三倍多。这就埋了今天第一个坑。

---

## 不能直接相减

学生最容易干的事，是两列相减：

```r
counts[, 2] - counts[, 16]
```

这行代码能跑，会给你一列数字，看着挺像样。

但它是垃圾。

因为有的肿瘤样本测了 8500 万条，有的正常样本只测了 2300 万条。就算这个基因在两个样本里的真实占比一模一样，测得多的那个样本，count 天然就会大一些。你减出来的是"测序量差异"，不全是"生物学差异"。

用个极端点的例子。假设：

| | 正常 | 肿瘤 |
|---|---:|---:|
| 总 reads | 1000 万 | 2000 万 |
| 基因 A | 100 | 180 |

基因 A 从 100 涨到 180，涨了 80%。但那是因为肿瘤样本测了两倍的数据。

算占比：正常样本里基因 A 占 `100 / 1000 万`；肿瘤样本里占 `180 / 2000 万`。折算一下，后者比前者还略低一点。

真实的生物学变化，被测序深度盖过去了。

---

## 别人是怎么处理这件事的

DESeq2 的做法值得花几分钟讲清楚，因为学生以后换工具也会遇到同样的问题。

思路是这样：既然每个样本的整体"放大倍率"不同，那就先把每个样本的倍率估出来，然后除掉它。

估的办法：先把每个基因在各样本间的 count 比值算出来，形成一堆比值，然后取这些比值的中位数。

为什么用中位数不用平均数？

假设一个样本里正好有几十个基因被强烈激活，count 涨了几十倍。这些基因的比值会非常夸张。用平均数，这几个基因就能把整个样本的倍率拉高，最后所有基因都被"过度校正"。用中位数，绝大多数基因说了算，少数异常基因影响不了大局。

课上会给学生看一组数：比值是 1.9、2.1、2.0、8.0。中位数是 2.0，平均数是 3.5。

问一句："如果没有那个 8.0，两个数是不是差不多？那要是有一百个 8.0 呢？"

---

## 为什么用负二项分布

先说泊松分布。它描述的是"单位时间内随机事件发生的次数"，一个特点：方差等于均值。

拿它来套 RNA-seq 的 count，方向是对的——count 也是非负整数，也是"计数"。

但会出问题。

同一组里的几个样本，同一个基因的 count 波动，往往比泊松分布预测的更大。这叫过度离散。原因不少：个体差异、建库效率、比对和注释的差别，都算。

于是换成负二项分布。它在泊松的基础上多估一个参数，叫离散度，允许方差大于均值：

```
方差 = 均值 + 离散度 × 均值²
```

离散度接近 0，就退回泊松。

DESeq2 里还有一步值得提：单个基因的离散度估计很不稳，尤其每组只有十几个样本的时候。所以它借用了"表达水平相近的基因，离散度也应该相近"这个规律，把估计值往一个趋势线上拉一拉，这叫收缩。这一步是 DESeq2 在小样本下比朴素方法稳的原因之一。

"负二项"里的"负"跟正负没关系，别被这个词吓到。

# 第二学时：跑通分析，读懂三个数

## 先看脚本里最关键的两处

打开 `01_diff_analysis.R`，别从头读，先找这两处：

```r
keep <- rowSums(counts >= 10) >= 6      # 低表达过滤
meta$condition <- relevel(factor(meta$condition), ref = "Normal")

dds <- DESeqDataSetFromMatrix(countData = counts, colData = meta,
                              design = ~ condition)
```

第一行先过滤：一个基因要在至少 6 个样本里 counts ≥ 10 才留下。60660 个基因里留下 23765 个。被过滤掉的绝大多数本来就没测到，留着只会增加多重检验的负担，还会让离散度估计乱掉。

第二行把 Normal 定为参考组。第三行说明：模型里只放 condition。

为什么不放批次？因为真实数据里没有干净可用的批次信息——30 个样本来自 30 个病人、十几个组织来源中心（TSS）。TSS 作为批次放进去会吃掉大量自由度，而病人是无法配对的（肿瘤和癌旁来自同一个人的只有 15 对里的一部分，且这批数据里不是我们刻意配对的）。所以设计就是最简单的两组比较，局限性要如实告诉学生。

如果哪天数据换成同一批样本既有治疗前又有治疗后，那才会用 `~ patient + condition` 这种配对设计。设计式不是越复杂越好，是要跟数据结构匹配。

对比在这里：

```r
res <- results(dds, contrast = c("condition", "Tumor", "Normal"), alpha = 0.05)
```

`c("condition", "Tumor", "Normal")` 的顺序决定了正负号。这样写，正数代表肿瘤里更高。

课上会问一句："如果把 Normal 和 Tumor 换个个儿，`log2FoldChange` 会变成什么样？"答不上来的同学，说明还没看懂符号是从哪来的。

---

## 结果表里最重要的三列

跑完脚本，`deg_table_all.csv` 每个基因一行。三列值得反复看。

**log2FoldChange**——变了多少，往哪个方向。

肿瘤比正常是 2 倍，`log2FC` 就是 1；是一半，就是 -1；`log2FC = 3.5`，大概是 11 倍。

**p 值**——"假如这个基因其实没变"，出现当前这么大或更大的差异，概率有多大。

注意这句话的主语：它说的是数据出现的概率，不是"这个基因有变化的概率"。这两句话经常被混，考试也爱考。

**padj**——同一批检验里有两万多个基因，校正之后还剩多少统计证据。

这一列最容易被忽略，但它决定着整张表的可信度。

课上给两张表对比：

| 基因 | log2FC | padj |
|---|---:|---:|
| A | 0.15 | 0.001 |
| B | 2.5 | 0.20 |

"只能选一个继续做实验，选哪个？"

没有标准答案。要看你想干什么。基因 A 变化太温和，做药靶没什么意思；基因 B 变化大但证据不足，可能是样本太少、组内波动太大。好的回答会同时提到这两点，而不是只说"选 log2FC 大的"。

---

## 两万多个基因，一千多个假阳性

这一段一定要算给学生看，因为很多人是第一次意识到问题的规模。

假设过滤后留下的 23765 个基因全都没差异。你仍然用 p < 0.05 当门槛：

```
23765 × 0.05 ≈ 1188
```

没有真实差异，光凭运气也能捞出近一千两百个"显著"基因。

这就是多重检验问题。

校正之后，`padj` 控制的不是"每个基因出错概率"，而是**整个发现列表里预期有多少比例是假的**。取 5%，意思是：你交上去的这份名单里，大概有 5% 是误报。

BH 方法的做法可以粗暴理解为：把所有 p 值从小到大排队，排在第 k 位的 p 值，要和小数 `k/23765 × 0.05` 比。找到最后一个还满足条件的位置，它前面的全部算显著。

课上问："把阈值从 0.05 放宽到 0.1，差异基因会变多还是变少？误报会变多还是变少？"

（学生答完，顺手把 `alpha = 0.05` 改成 `0.1` 再跑一遍，用眼睛看。比讲十遍有用。）

## 跑之前先猜一下结果

这一步很多老师会跳过，但它其实挺关键。

让学生开跑之前，先猜：差异基因大概几十个、几百个还是几千个？

猜完再跑：

```bash
Rscript scripts/01_diff_analysis.R  ../data  ./results
```

控制台应该出现：

```
Loaded 60660 genes x 30 samples
Normal Tumor
    15    15
Genes passing the low-count filter: 23765 / 60660
Significant DEGs (padj<0.05, |log2FC|>1): 7283
   up-regulated: 4355 | down-regulated: 2928
```

看到"猜 500 个"的同学对着 7283 发愣，这也是个很好的教学时刻——真实的肿瘤 vs 癌旁转录组差异非常大，成千上万个基因在变。差异基因多，反而更难挑靶点，因为"变了"的基因太多了。

数字不对怎么办，按这个顺序查，别跳步：

1. 命令行两个参数对不对（`.` 或 `../data` 是数据目录，`./results` 是输出目录）；
2. `sample_meta.csv` 里 `condition` 是不是只有 Normal 和 Tumor 两种值；
3. `all(colnames(counts) == meta$sample_id)` 这一句过没过；
4. 低表达过滤那行的阈值有没有被改动。

顺便把 EGFR 找出来看一眼。脚本最后会单独打印它：

```
EGFR (course target, for discussion):
             gene_id baseMean log2FoldChange    pvalue      padj
1 ENSG00000146648.19 6405.124     -0.2059369 0.4651961 0.5638075
```

表达没有显著变化。`padj` 约 0.56，`log2FC` 约 -0.21，基本是平的。

这里必须停下来讲：**EGFR 是有名的肺癌靶点，为什么表达分析看不到它？**

答案分两层：

第一层，技术上的。TCGA 的这批肿瘤是"混合瘤组织"，里面除了肿瘤细胞还有成纤维细胞、免疫细胞、正常上皮细胞。EGFR 的 mRNA 本来就主要来自上皮细胞，肿瘤和癌旁的表达差异被组织构成稀释掉了。而且真正决定 EGFR 靶点地位的，是**激活突变、基因扩增、蛋白磷酸化**这类事件，它们不一定改变总 mRNA 量。

第二层，观念上的。"差异表达"和"是不是好靶点"是两个问题。今天数据里就有活生生的例子：一个教科书级的靶点，在表达层面完全是阴性的。谁要是把"只有 DEG 才是靶点"当规则，今天就会被数据打脸。

那 EGFR 凭什么进靶点名单？先卖个关子，第三学时用突变数据回答。

## 火山图：能读什么，不能读什么

横轴 `log2FoldChange`，纵轴 `-log10(padj)`。

板块很清楚：右上角是肿瘤里显著升高的，左上角是显著降低的，中间的灰点是不满足门槛的。两条虚线是 `log2FC = ±1`，一条横线是 `padj = 0.05`。

学生第一眼都会看右上角。这时候问一句："纵轴最高的那个点，是表达量最高的基因吗？"

不是。纵轴只代表统计证据的强度，跟表达量的绝对值没关系。一个表达很低的基因，只要组内很稳定，也可能冲到上面去。

再问："这张图能告诉你哪个基因是肿瘤的驱动基因吗？"

不能。它只能告诉你两组的平均值不一样。

应该让学生自己动手写一句"这张图不支持的结论"，比如：

> 右上角的基因一定是致病基因。

这句话写出来，学生自己就发现问题了——图上没有任何信息能支持"致病"两个字。

顺带看一眼真实的 top 上调基因：MAGEA6、MAGEA3、HOXC12、PRAME、NKX2-4，全是**睾丸抗原/发育转录因子**这一类。它们显著、幅度巨大，但你说它们是肺腺癌的驱动靶点吗？大多数不是——它们更多反映"肿瘤去分化、重新打开胚胎程序"。这就是活教材：**统计最强 ≠ 最值得做药**。

# 第三学时：从基因列表，到通路，再到候选

## 七千个基因摆在你面前，看不出所以然

7283 个基因名，打印出来几十页。盯着看，看不出机制。

富集分析换了个问法：

> 已知的生物学过程有成百上千个。我这 7283 个基因，落在哪些过程里的比例，明显高于随机情况？

这就是 `02_enrichment.R` 干的事。运行：

```bash
Rscript scripts/02_enrichment.R  ../data  ./results
```

脚本流程：读差异表、按阈值筛显著基因、用 `bitr()` 把基因名转成 Entrez ID、**把过滤后实际参与检验的基因作为背景集（`universe`）显式传给两个富集函数**、跑 GO 生物学过程富集与 Reactome 通路富集，最后画 dotplot 出表。

注意：GO 用的注释包是 `org.Hs.eg.db`，Reactome 用的是 `reactome.db`，两个都在本地，**不联网也能跑**。这是刻意换的——KEGG 的富集要实时下载注释，很多校园网络会拦，课上卡十分钟很正常。想看 KEGG，可以另开 Enrichr 网页端（`https://maayanlab.cloud/Enrichr`），上传 `results/deg_symbols.txt`，选 KEGG_2021_Human，作为交叉验证。

真实数据跑出来什么样？

- GO BP 613 个条目显著，最靠前的是 extracellular structure organization（细胞外结构组织）、external encapsulating structure organization、extracellular matrix organization（细胞外基质组织），都是 150 多个基因；
- 往下是 regulation of monoatomic ion transport、regulation of system process、regulation of membrane potential、humoral immune response、cell-cell adhesion；
- Reactome 119 个条目，第一名是 GPCR ligand binding（169 个基因），第二名是 Extracellular matrix organization（138 个基因）。

这张结果单，学生要能读出一件事：**肿瘤 vs 癌旁的差异，很大一部分是"组织构成和微环境"的差异**（基质、免疫细胞、离子转运），而不是单一癌基因的激活。这跟"我想找一个分子靶点"之间，还需要一次跳跃。

## 背景集：最容易被糊弄过去的一步

富集结果里有两个数经常被念错。

第一个是 Count：我的基因列表里，有多少个落在这一条通路里。

第二个是背景（universe）：我从多少基因里挑出了这 7283 个。

两个数必须一起看。举例：

- 背景 23765 个基因，通路有 200 个基因，我命中了 12 个；
- 背景 500 个基因，通路有 200 个基因，我命中了 12 个。

第二个情况明显更"厉害"，但很多报告只写"命中 12 个基因"。

**这是本课最容易犯的代码级错误。** `enrichGO()` 与 `enrichPathway()` 都有 `universe` 参数，而**不传它并不等于"自动用你的输入"**：`enrichGO` 会退回 `org.Hs.eg.db` 里全部被注释的基因，Reactome 会退回它自己注释的全部基因——分母里于是混进了成千上万个"这批实验根本检测不到"的基因，p 值被算得偏小，显著条目虚高。正确做法是把**通过低表达过滤、真正进入差异检验的基因**映射成 Entrez 后显式传入：

```r
universe <- bitr(unique(deg$symbol[!is.na(deg$pvalue)]),
                 fromType = "SYMBOL", toType = "ENTREZID", OrgDb = org.Hs.eg.db)$ENTREZID
universe <- unique(universe)      # 本课实测：23742 个符号 -> 19492 个 Entrez

enrichGO(gene = entrez$ENTREZID, universe = universe, ...)
enrichPathway(gene = entrez$ENTREZID, universe = universe, ...)
```

背景集应该是什么？是"有机会被检验到的基因"。这份数据里过滤后剩 23765 个基因，那 23765 就是背景。如果把背景设成"全部人类基因（两万个）"或"genome 全注释"，等于把那些根本没进表的基因也算进去当分母，显著性会被高估。

还有一种错误，学生写报告时特别爱犯：

> 上调基因和下调基因混在一起做富集，然后写"这条通路被激活"。

上调下调方向相反，掺在一起只能说"这条通路里的基因有变化"，不能说激活或抑制。想谈方向，就分开做两次。

## 交集：从 7283 个到 78 个

第三个脚本做三件事，先看第一件：

```r
candidates <- inner_join(sig, panel, by = "symbol") %>%
  arrange(desc(log2FoldChange)) %>%
  mutate(rank = row_number())
```

把显著差异基因和 `druggable_panel.csv`（247 个已知可成药基因）取交集，按变化幅度从大到小排个序。

```bash
Rscript scripts/03_target_shortlist.R  ../data  ./results
```

出 `target_shortlist.csv`，实测 78 行，列是 `rank, symbol, panel_class, known_drug_class, log2FoldChange, padj, baseMean, n_mutated, mutation_examples`。

top5 是：TERT、HTR3A、TOP2A、CDKN2A、SLC6A3。

**先说清楚这一步的地位，否则后面容易读歪。** 这份名单是**假设无关（hypothesis-free）的全基因组扫描**产物：它不预设任何候选人，是唯一一个"手里没有任何先验知识也能跑"的筛选。真实项目里它就是第一层，通常还会并行做第二层。它给出的 78 个不是判断题的答案，而是**待验证的候选池**——列表里的 TOP2A 是已经上市的拓扑异构酶抑制剂的靶点（依托泊苷、拓扑替康这类药在肺癌里真的在用），CCNE1、CDKN2A、CHEK1 属于细胞周期/增殖通路，都是有药在做的东西。

教官课上追问三个问题：

"从 7283 个变成 78 个，砍掉了什么？"

"不在面板里的基因，是不是就一定做不了药？"

"这 78 个里，有 EGFR 吗？"（没有。）

第二个问题的答案是否定的。面板只是"目前已知有药在做的靶点清单"，它记录的是历史，不是可能性。真要严格讨论可成药性，得回到课程二那种结构层面的分析。

第三个问题先别急着下结论——"不在名单里"不等于"这步筛错了"。真正要问的是：**表达这个测量，能不能看见 EGFR 这类靶点的变化方式？** 带着这个问题往下看第二类证据。

## 第二类证据：突变

第一个脚本还把每个肿瘤的突变数据读进来了（`mutation_matrix.csv`，14 例有 WXS 的肿瘤 × 14 个驱动基因；第 15 例没有 MAF 文件，按未知处理）。第三个脚本列出"有非沉默突变的基因"，输出 `mutation_driven_candidates.csv`。

`n_mutated` 的分母是**有突变数据的 14 例**，不是 15 例。还有一件必须对学生说清的事：这 15 例是**筛选过的教学子集**（见 `data/README.md`：特意包含 2 例 EGFR 激活突变），所以这批数据只能用来演示方法，**不能用它估计 TCGA-LUAD 人群里 EGFR 的突变率**；EGFR 最后胜出，也部分受了样本选择与预设驱动基因面板的影响。

打印出来是这样的（节选）：

| symbol | n_mutated | mutation_examples | deg_status | log2FoldChange | padj |
|---|---:|---|---|---:|---:|
| TP53 | 8 | p.C277F; p.Q317*; ... | padj<0.05 but \|log2FC\|<1 | 0.72 | 4.0e-4 |
| KRAS | 6 | p.G12C; p.G12S; p.G12V; ... | padj<0.05 but \|log2FC\|<1 | 0.78 | 1.3e-3 |
| STK11 | 3 | p.Q220*; p.S216F; ... | not significant | 0.10 | 5.1e-1 |
| RET | 2 | p.T350N; p.E901K | not significant | 0.45 | 3.0e-1 |
| KEAP1 | 2 | p.K287*; p.D236N | not significant | 0.26 | 1.9e-1 |
| **EGFR** | **2** | **p.E746_A750del; p.L858R** | **not significant** | **-0.21** | **5.6e-1** |
| SMARCA4 | 1 | p.E1362K | not significant | 0.46 | 1.1e-1 |
| PIK3CA | 1 | p.P104L | not significant | -0.23 | 2.2e-1 |
| ROS1 | 1 | p.I1374F | not significant | -0.61 | 2.3e-1 |

（`deg_status` 里的 "not significant" 指 padj≥0.05；TP53/KRAS 是 padj 显著但幅度不足 |log2FC|>1，所以也没进 DEG 名单——正好说明"统计显著"和"差异够大"是两件事。n_mutated 是**样本数**，同一个基因可能一例携带多个变异，例如 TP53 的 8 例里共有 9 个变异。）

EGFR 出现了，`n_mutated = 2`。两例分别是外显子 19 缺失（E746_A750del）和 L858R——这两个是教科书上最经典的 EGFR 激活突变，也是 NSCLC 里 EGFR-TKI 的用药依据。

所以 EGFR 进靶点名单靠的不是表达，是**突变**。

这一段要讲三个层次：

**第一层，突变和表达是两类证据。** 表达回答"这个基因的 mRNA 在肿瘤里是不是更多"；突变回答"这个基因的蛋白产物在肿瘤里是不是被改坏了、被持续激活了"。一个基因可以表达完全不变，但蛋白被一个点突变锁死在开启状态，那它就是驱动。EGFR 就是标准例子。

**第二层，有突变不等于有功能。** 表里的 RET p.T350N、ROS1 p.I1374F、SMARCA4 p.E1362K 在 ClinVar 与 CIViC 里都查不到记录——**查不到不等于阴性**，只说明没人提交过或没人做过功能实验，所以只能写"未明"。要判断哪些突变有功能，得查 CIViC、OncoKB、COSMIC 这类数据库，或做功能实验。本课只做到"发现"，不做到"定性"。

**第三层，数据本身有窟窿。** 15 例肿瘤里只有 14 例有突变数据——TCGA-05-4245 没有 WXS 文件。**没有突变记录 ≠ 野生型**。另外 MAF 文件只记录 SNV 和小片段插入缺失，**看不到基因扩增和融合**；EGFR 扩增、ALK/ROS1 融合这些真实肺癌里很重要的驱动事件，本课数据里根本没有。写报告时必须把这层局限写出来。

## 什么不能当筛选条件

进了漏斗之前，先把两个诱惑当面拒掉。它们是这一课最容易犯、也最隐蔽的两个错：

1. **"这个基因有没有已经上市的药？"——不能当筛选条件。** 这是拿已知答案反推过程。EGFR 之所以人人皆知，恰恰因为它已经有药；拿"有没有药"当筛子，等于把结论当证据用，而且会把所有真正的新靶点全部刷掉——按这个标准，任何还没有药的东西都不配做靶点，那就不可能发现新药。
2. **"这个靶点能不能查到文献？"——也不能。** 文献多少取决于这个靶点出名多久，跟它是不是好靶点没关系；而且文献是**后验**的：你还没做，怎么会有文献。

那漏斗里能放什么？**只放肿瘤和分子自身的事实**：

1. **这个基因在病人身上被打坏了吗？**——有非沉默突变（来自 MAF，与表达无关）；
2. **这个变异是把蛋白"打开"还是"关掉"？**——我们要做的是"抑制它"，所以需要功能获得型（激活）变异；功能缺失型（抑癌基因被打坏）要的是恢复功能，不是抑制，不能用同一套药去解决；意义未明的变异只能如实标"未知"。**这一层分两半做**：无义、移码这类**截短变异由脚本自动判**（蛋白都被打坏了，不可能"打开"）；错义、框内缺失这类**查库判**——`data/lookup_variant.py` 帮你把 ClinVar 与 CIViC 的记录拉出来，但脚本只给记录、不给结论，结论与证据等级要你来写；
3. **蛋白在不在我们要设计的那种药够得着的地方？**——课程三做的是 mini-protein / 抗体这类大分子，进不了细胞膜。**这是我们对模态的选择，不是靶点的优劣**：换成小分子，胞内蛋白反而更合适。这一层**由脚本查询 UniProt 自动标注**（`data/annotate_targets.py`）：有胞外域才是大分子够得着的，脂锚在膜内侧的 KRAS 不算。

把 9 个突变候选按这三层摆开：

| 候选 | 本队列突变 | 变异功能 | 定位 | 大分子路线 | 卡在哪一层 |
|---|---|---|---|---|---|
| **EGFR** | 2/14（p.E746_A750del、p.L858R） | 功能获得（查库：CIViC / ClinVar / 文献） | 有胞外域 | **过** | — |
| KRAS | 6/14（G12C/G12S/G12V/G12A） | 功能获得（查库：ClinVar + CIViC） | 胞内 | 第三层 | 换小分子路线就轮到它 |

| RET | 2/14（T350N、E901K） | 意义未明（查库：两库都无记录） | 有胞外域 | 第二层 | 没有功能证据；**查不到 ≠ 阴性** |

| SMARCA4 | 1/14（E1362K） | 意义未明（同上） | 细胞核 | 第二层 | 同上 |

表达层 top 的去向也说清楚：TOP2A 是核内的拓扑异构酶、CDKN2A/CCNE1 也在胞内，它们没掉队，而是**进了候选池、作为后续依赖实验（敲除/RNAi/CRISPR）的对象**——只是走不了本课这条"结构 + 大分子设计"的路。

出处清单与"哪些是事后佐证"的标注见 `docs/文献依据.md`。

## 三层叠起来：从 9 个到 1 个

到这里手里有两份互不相干的名单：表达驱动的 78 个、突变驱动的 9 个。脚本最后一步用上面那三条（只看肿瘤与分子的事实）往下筛：

```
1. 本队列里有非沉默突变               9 个基因
2. + 变异把蛋白"打开"（功能获得）      3 个基因   （EGFR、KRAS、PIK3CA）
3. + 我们要做的大分子够得着           1 个基因   （EGFR）
```

第二层先砍掉谁：TP53、STK11、KEAP1 这三个基因都是**功能缺失**类型，但请看清判定是怎么来的——**判定以变异为单位，不是整个基因贴一个标签**：

| 基因 | 自动判定的截短变异 | 查库后判定为功能受损的错义变异 | 查库后仍意义未明 |
|---|---:|---:|---:|
| TP53 | 1 条（Q317*） | 4 条（R156P、R248L、R273C、Y236C） | 4 条 |
| STK11 | 2 条（Q220*、Q37Pfs*123） | 0 | 1 条（S216F） |
| KEAP1 | 1 条（K287*） | 0 | 1 条（D236N） |

截短变异（无义/移码）由 MAF 的 `variant_class` **自动判**——蛋白被打坏了，不可能"打开"；但同一个基因上的错义变异**必须逐条查库**：TP53 的 4 条错义变异在 ClinVar/CIViC 里有明确的功能受损证据，另外 4 条既无记录也无可用的功能实验。如果按"一个基因只要有一条截短变异就整体算功能缺失"去讲，那 4 条判不出结果的变异就被悄悄吞掉了——这正是脚本按变异判定、再汇总到基因的原因（汇总表里 `n_gof / n_lof / n_uncertain` 三列就是干这个的）。

RET、ROS1、SMARCA4 的变异是**意义未明**：T350N、E901K、I1374F、E1362K 在 ClinVar 与 CIViC 里都查不到记录。**查不到不等于阴性**——数据库没有记录只说明没人提交过或没人做过功能实验，所以只能写"未明"，不能写"野生型"，更不能当成驱动事件。把"意义未明"当成"能用"是最常见的一类误读。

PIK3CA 那一行要在课上停一下：P104L 在 ClinVar 里被判为**致病**（5 个提交者、无冲突），但关联的是**生殖系过度生长综合征**（Cowden 综合征 / PIK3CA-related disorder）——那是一个由 PIK3CA 功能获得驱动的疾病，所以这条记录支持"激活"；可它在体细胞层面不是经典热点（E542K/E545K/H1047R），CIViC 里也没有条目（本队列位点 chr3:179199136，与 ClinVar 记录一致）。正确的写法是 `gain_of_function` + 证据等级 `moderate` + 注明语境——既不一句"VUS"敷衍，也不假装它有肿瘤驱动证据。

第三层砍掉 KRAS 与 PIK3CA：KRAS 的 6 例全是 12 号密码子激活突变，PIK3CA 也有激活证据，但两者都在**胞内**（KRAS 是脂锚在膜内侧，不是胞外域；PIK3CA 是胞质激酶）。**这一层砍的不是"它不够好"，而是"它不适合我们选定的那种药"。** 脚本会把这句对照打印出来：同一条数据、改做小分子，答案就是 KRAS 与 PIK3CA（KRAS 的 G12C 抑制剂后来真的上市了——但注意，这是**事后**才知道的佐证，不能拿来当筛选条件）。

EGFR 的两例是外显子 19 缺失和 L858R，都是教科书级的激活事件（19del/L858R 预测 TKI 敏感性：Lynch 2004, PMID 15118073；Paez 2004, PMID 15118125；厄洛替尼的生存获益：Shepherd 2005, PMID 16014882；T790M 耐药与三代药：Pao 2005, PMID 15737014、Jänne 2015, PMID 25923549）。这些文献在课上的位置是**事后佐证**：先由数据把方向定下来，再用文献确认这个方向有人走过。

脚本把结果写成两张表：

- `integrated_candidates.csv`：9 个突变基因 + 变异功能与证据等级 + UniProt 定位 + 药物背景（最后一列只作参考，不参与筛选），用来给学生看每一层砍掉了谁；
- `target_recommendation.csv`：三层全过的那一个——**EGFR，rank 1**。

还有一个数字必须当场指出：**78 个表达驱动候选与这条漏斗的交集是 0**。两份名单一个都不重叠。

这个 0 该怎么读？**不是"表达筛选白做了"，而是这两层测的是两件不同的事。** 表达层是无假设扫描（不预设候选，谁都能进），它给出的 78 个是真实候选，只不过它们要确证还差一层实验——表达高 ≠ 肿瘤依赖它，得做敲除/RNAi/CRISPR 这类**依赖实验**才能把"伴随现象"和"真正的命门"分开，而这一层不在本课时间范围内。漏斗走的是另一条路：找一个**验证成本低得多**的候选——带激活突变（已经有因果线索）、露在细胞表面（结构上能设计）。EGFR 两条全中，所以能从 9 个基因里直接跳到下一课做结构验证。

一句话：两层不是对错关系，是"扫描广度"和"验证成本"的取舍。

## EGFR 为什么不在 shortlist 里

这是今天最值得抠的细节。

- `deg_table_all.csv` 里按 `padj` 排，EGFR 排在很后面（padj ≈ 0.56，不显著）；
- `target_shortlist.csv` 里根本没有 EGFR，因为那个表的前提是"先得是 DEG"；
- `mutation_driven_candidates.csv` 里 EGFR 有 2 例激活突变；
- 三层漏斗（突变 → 功能获得 → 大分子够得着）走完，`target_recommendation.csv` 里只剩 EGFR 一个。

四张表，四个结论，数据没毛病。

问题出在**筛选顺序**：`target_shortlist.csv` 的第一步是"取 DEG"，这个门槛一设，EGFR 就被筛掉了。要救它回来，必须靠另一条通路——突变表；再往下走，还得靠定位和药物类型。

以后写报告、做汇报，别人问"EGFR 是不是最好的靶点"，标准答案是："**先问在哪个层面、哪种模态下。**表达层面它在数据里没有证据；突变层面它 2/14 有激活突变（第 15 例无 MAF）；定位层面它在细胞表面，我们做的大分子够得着；而 KRAS 在同一份数据里同样是功能获得，只是它需要小分子——所以准确的说法是'按大分子路线，EGFR 是这批数据里最站得住的那个'，而不是'EGFR 是这批数据里最好的靶点'。"只甩一句"EGFR 是靶点"，是不完整的；只甩一句"EGFR 表达不显著所以不是靶点"，更是错的；反过来说"78 个候选里没有它，所以表达筛选白做了"，同样错——那 78 个是有效候选池，只是每一个都还要再过一层依赖实验才能定性；EGFR 因为带激活突变、露在表面、有现成药，可以直接跳到结构验证，这条路更短。

### 第二件：让 AI 写一段统计


拿回来以后看三处：用的是 `padj` 还是 `pvalue`；NA 是怎么处理的；跑出来的数跟 7283 / 4355 / 2928 对不对得上。

很多时候 AI 会给一版"能跑但数不对"的代码，正好用来说事。

### 第三件：改阈值，考的是同步性

```
把阈值改成 padj < 0.01 且 abs(log2FoldChange) > 1.5。
同时检查：筛选条件、火山图配色、两条竖线、一条横线，哪些地方要跟着改。
把所有需要改的地方列出来。
```

这个任务的坑在于：只改 `filter()` 不改画图那几行，图和数字就对不上了。图上的线还画在 ±1，可你的筛选早就变成 ±1.5 了。

学生自己跑一遍，一眼就能看出来。

### 第四件：读报错

直接把真实的报错扔给 AI：

```
Error in `all(colnames(counts) == meta$sample_id)`: 
```

让它给排查顺序，然后照着查：列名对不对、样本顺序对不对、`read.csv` 有没有写 `row.names = 1`、manifest 顺序和矩阵列顺序是否一致。

## 拿回来的代码，怎么审

给学生一张清单，逐条打钩：

- 变量名是我数据里真实存在的列名，不是 AI 编的
- 用的是 `padj`，不是 `pvalue`
- NA 怎么处理写清楚了
- 阈值、配色、参考线三处同步了
- 分组方向没弄反（Tumor / Normal）
- 里面的路径是我自己的，不是 AI 编的绝对路径

然后本地跑，核对（`significance` 那一列不存在于 csv 里，是画图时临时造的，所以直接按条件数）：

```r
res_df <- read.csv("results/deg_table_all.csv")
nrow(res_df)                                                            # 23765
sum(res_df$padj < 0.05 & abs(res_df$log2FoldChange) > 1, na.rm = TRUE)  # 7283
```

最后交一份 `ai_code_review.md`，写清楚：我给了 AI 什么、用了什么提示词、它返回了什么、我查出什么问题、跑出来什么结果、我接受或拒绝了哪部分。

一句话：**AI 可以帮你写代码，但报告里的结论只能来自你自己跑出来的数字。**

## 从差异基因到药靶，中间隔着好几层

7283 个差异基因，只是第一层。想走到"值得做成药"，得补：

**表达差异**——这层今天做完了。

**突变/结构性改变**——今天做了一半。找到了 EGFR 的激活突变，但没做功能判定，也没查扩增和融合。

**通路证据**——今天做了一半。能看到细胞外基质、细胞周期、免疫过程排在前面，但别把"富集"当成"机制"。

**因果证据**——敲掉这个基因，疾病表型会不会变。需要敲除、敲低、过表达实验。今天完全没有。

**临床证据**——患者队列里，这个基因的表达或突变跟预后、疗效有没有关系。今天只是用了队列数据做组间比较，没有做生存/疗效关联。

**可成药证据**——有没有可结合的口袋，或者已有药物。课程二看结构，课程三做设计。

**安全性证据**——正常组织是不是也依赖它。今天最缺的就是这层，也最容易被忽略。

上课的时候让学生把"我们今天完成了哪几层"圈出来，很多人会发现自己高估了。

## EGFR：好在哪，哪里可疑

支持它的理由：

- **14 例有突变数据的肿瘤里 2 例携带经典激活突变**（E746_A750del、L858R），这是本课数据里最硬的证据
- 受体酪氨酸激酶，**有胞外域**（UniProt 自动标注，不是人工写的），大分子够得着
- 现实中已经有针对它的获批药物（西妥昔单抗、奥希替尼等），说明这条路临床上走通过
- 课程二的晶体结构（1M17、1YY9）显示它有明确的可结合口袋

必须同时写的反证：

- 表达层面**没有证据**：log2FC ≈ -0.21、padj ≈ 0.56，mRNA 没变
- 突变阳性只占 2/14（且这批 15 例是**筛选过的**教学子集：含 2 例 EGFR 激活突变，因此不能用来估计人群突变率），"有突变"也不等于"肿瘤依赖这条通路"
- MAF 只覆盖 SNV/indel，**看不到 EGFR 扩增**，也看不到 ALK/ROS1 融合；真实肺癌的驱动谱比这宽
- 15 例肿瘤里有 1 例根本没有突变数据，"没查到突变"不等于"没有突变"
- EGFR 在正常上皮里也表达，抑制它会有皮肤和消化道毒性
- 不同患者对 EGFR 抑制剂的反应差得很远，需要按突变亚型分层

讨论时给学生一个"必须从对面挑刺"的任务：两个人一组，一个为 EGFR 辩护，一个专门拆台，最后合写一段结论。

## 结论该怎么写

先看一段不能用的：

> EGFR 是肺癌的关键靶点，表达检测也支持，可以做药。

问题在哪？这句话里"表达检测也支持"是**编的**，本课数据恰好不支持；"可以做药"也没有证据兜底。

再看一段能用的：

> 在 TCGA-LUAD 的 15 例肿瘤 vs 15 例癌旁中，23765 个过滤后基因里有 7283 个满足 `padj < 0.05` 且 `|log2FC| > 1`（上调 4355、下调 2928）。以过滤后实际参与检验的 23742 个基因为背景（映射到 19492 个 Entrez ID），GO BP 有 613 个条目显著，Reactome 有 119 条；两侧 top 项都落在细胞外基质组织（GO：159 基因；Reactome：138 基因）等微环境相关过程。7283 个 DEG 与 247 个可成药基因取交集得到 78 个候选（top5：TERT、HTR3A、TOP2A、CDKN2A、SLC6A3），**EGFR 不在其中**：其表达无显著差异（log2FC ≈ -0.21，padj ≈ 0.56）。EGFR 进入靶点名单的依据是突变数据——15 例肿瘤中 2 例携带激活突变（E746_A750del、L858R）。本课数据只能支持"EGFR 在部分患者中具备可成药驱动事件"，不能证明整体依赖：样本量仅 15+15，有突变数据的 14 例中检出 2 例，无蛋白与功能实验，MAF 未覆盖扩增与融合，且有 1 例肿瘤缺突变数据。下一步需在细胞模型中验证 EGFR 依赖性与蛋白活化状态，并补做结构层面的可成药性分析。

两段话的区别，就四件事：数据是什么、看到了什么、支持什么、还差什么。写报告就照这个骨架填。
