# 课程一讲义：从一张表达矩阵，到一个候选靶点

四个学时，180 分钟。配三个脚本，`01_diff_analysis.R`、`02_enrichment.R`、`03_target_shortlist.R`。

## 开课前先说一件事

上课第一分钟，投影上放的就是这张表：`expression_matrix.csv`。

10000 行，12 列。行是基因，列是样本。S01 到 S06 是正常肺组织，S07 到 S12 是肺腺癌。格子里的数都是整数，有的 0，有的几十万。

就这一张表。四个小时以后，每个学生要从里面挑出一个基因，说清楚为什么它值得做药靶，还得说清楚这个理由哪里不牢靠。

这两件事一样重要。只会挑基因、不会说哪里不牢靠的人，以后写基金、做汇报、做投资尽调，都会被人问住。

数据是统计合成的，不含真实病人信息，但保留了真实分析里的那些麻烦：测序深度不一样、基因均值和方差相关、基因数远多于样本数、还混了批次。教学用真数据会有隐私问题，用干净数据又练不到本事，所以做了这么一份。

先记住几个数，后面反复要用。学生的机器跑出来应该跟这些数对得上：

```
padj < 0.05 且 |log2FC| > 1  →  116 个差异基因（上调 76，下调 40）
EGFR：完整表按 padj 排第 2，log2FC 约 3.51
可成药面板 247 个基因，交集后剩 18 个候选，EGFR 在这 18 个里排第 1
```

如果前三个数对不上，先别急着改结果，回头查数据路径、样本注释和列顺序。查完再说。

# 第一学时：count 到底是什么东西

## 先看这张表本身

在 RStudio 里敲这三行：

```r
counts <- read.csv("expression_matrix.csv", row.names = 1, check.names = FALSE)
dim(counts)
head(counts[, 1:4], 3)
```

`dim` 会告诉你 10000 和 12。前几行长这样：基因名在前面，后面跟着几列整数。

这个"整数"很重要。

RNA-seq 做的事情，简单说就是：把样本里的 RNA 提出来、逆转录成 cDNA、建库、上机测序。测序仪吐出来一堆短序列，叫 reads。这些 reads 经过质控和比对，被分配到各个基因头上。

所以某个基因在某个样本里的 count，就是"这次测序里，有多少条 reads 落到了这个基因上"。

注意这句话的措辞：是 reads 条数，不是分子个数，不是浓度。

很多同学第一遍读不出区别。等做到第三步就知道厉害了——两个样本测的 reads 总数都不一样，你拿条数直接比，比的是什么？

再敲一行：

```r
colSums(counts)
```

12 个数，大概在 1500 万到 1900 万之间。

看出来了吗？不相等。这就埋了今天第一个坑。

---

## 不能直接相减

学生最容易干的事，是两列相减：

```r
counts[, "S07"] - counts[, "S01"]
```

这行代码能跑，会给你一列数字，看着挺像样。

但它是垃圾。

因为肿瘤样本可能测了 1900 万条，正常样本只测了 1500 万条。就算这个基因在两个样本里的真实占比一模一样，测得多的那个样本，count 天然就会大一些。你减出来的是"测序量差异"，不全是"生物学差异"。

用个极端点的例子。假设：

| | 正常 | 肿瘤 |
|---|---:|---:|
| 总 reads | 1000 万 | 2000 万 |
| 基因 A | 100 | 180 |

基因 A 从 100 涨到 180，涨了 80%。但那是因为肿瘤样本测了两倍的数据。

算占比：正常样本里基因 A 占 `100 / 1000 万`；肿瘤样本里占 `180 / 2000 万`。折算一下，后者比前者还略低一点。

真实的生物学变化，被测序深度盖过去了。

---

## 别人是怎么处理这件事的

DESeq2 的做法值得花几分钟讲清楚，因为学生以后换工具也会遇到同样的问题。

思路是这样：既然每个样本的整体"放大倍率"不同，那就先把每个样本的倍率估出来，然后除掉它。

估的办法：先把每个基因在各样本间的 count 比值算出来，形成一堆比值，然后取这些比值的中位数。

为什么用中位数不用平均数？

假设一个样本里正好有几十个基因被强烈激活，count 涨了几十倍。这些基因的比值会非常夸张。用平均数，这几个基因就能把整个样本的倍率拉高，最后所有基因都被"过度校正"。用中位数，绝大多数基因说了算，少数异常基因影响不了大局。

课上会给学生看一组数：比值是 1.9、2.1、2.0、8.0。中位数是 2.0，平均数是 3.5。

问一句："如果没有那个 8.0，两个数是不是差不多？那要是有一百个 8.0 呢？"

---

## 为什么用负二项分布

先说泊松分布。它描述的是"单位时间内随机事件发生的次数"，一个特点：方差等于均值。

拿它来套 RNA-seq 的 count，方向是对的——count 也是非负整数，也是"计数"。

但会出问题。

同一组里的几个样本，同一个基因的 count 波动，往往比泊松分布预测的更大。这叫过度离散。原因不少：个体差异、建库效率、比对和注释的差别，都算。

于是换成负二项分布。它在泊松的基础上多估一个参数，叫离散度，允许方差大于均值：

```
方差 = 均值 + 离散度 × 均值²
```

离散度接近 0，就退回泊松。

DESeq2 里还有一步值得提：单个基因的离散度估计很不稳，尤其样本只有 3 个、6 个的时候。所以它借用了"表达水平相近的基因，离散度也应该相近"这个规律，把估计值往一个趋势线上拉一拉，这叫收缩。这一步是 DESeq2 在小样本下比朴素方法稳的原因之一。

"负二项"里的"负"跟正负没关系，别被这个词吓到。

# 第二学时：跑通分析，读懂三个数

## 先看脚本里最关键的两行

打开 `01_diff_analysis.R`，别从头读，先找这两处：

```r
meta$condition <- relevel(factor(meta$condition), ref = "Normal")

dds <- DESeqDataSetFromMatrix(countData = counts, colData = meta,
                              design = ~ batch + condition)
```

第一行把 Normal 定为参考组。第二行说明：模型里既放了批次，也放了我们真正关心的 condition。

为什么批次必须放进去？因为这份数据的正常样本和肿瘤样本来自不同批次。如果模型里不写批次，它就会把批次差异当成疾病差异报给你，你还看不出来。

对比在这里：

```r
res <- results(dds, contrast = c("condition", "Tumor", "Normal"), alpha = 0.05)
```

`c("condition", "Tumor", "Normal")` 的顺序决定了正负号。这样写，正数代表肿瘤里更高。

课上会问一句："如果把 Normal 和 Tumor 换个个儿，`log2FoldChange` 会变成什么样？"答不上来的同学，说明还没看懂符号是从哪来的。

---
 
## 结果表里最重要的三列

跑完脚本，`deg_table_all.csv` 每个基因一行。三列值得反复看。

**log2FoldChange**——变了多少，往哪个方向。

肿瘤比正常是 2 倍，`log2FC` 就是 1；是一半，就是 -1；`log2FC = 3.51`，大概是 11 倍。

**p 值**——"假如这个基因其实没变"，出现当前这么大或更大的差异，概率有多大。

注意这句话的主语：它说的是数据出现的概率，不是"这个基因有变化的概率"。这两句话经常被混，考试也爱考。

**padj**——同一批检验里有一万个基因，校正之后还剩多少统计证据。

这一列最容易被忽略，但它决定着整张表的可信度。

课上给两张表对比：

| 基因 | log2FC | padj |
|---|---:|---:|
| A | 0.15 | 0.001 |
| B | 2.5 | 0.20 |

"只能选一个继续做实验，选哪个？"

没有标准答案。要看你想干什么。基因 A 变化太温和，做药靶没什么意思；基因 B 变化大但证据不足，可能是样本太少。好的回答会同时提到这两点，而不是只说"选 log2FC 大的"。

---

## 一万个基因，五百个假阳性

这一段一定要算给学生看，因为很多人是第一次意识到问题的规模。

假设一万个基因全都没差异。你仍然用 p < 0.05 当门槛：

```
10000 × 0.05 = 500
```

没有真实差异，光凭运气也能捞出五百个"显著"基因。

这就是多重检验问题。

校正之后，`padj` 控制的不是"每个基因出错概率"，而是**整个发现列表里预期有多少比例是假的**。取 5%，意思是：你交上去的这份名单里，大概有 5% 是误报。

BH 方法的做法可以粗暴理解为：把一万个 p 值从小到大排队，排在第 k 位的 p 值，要和小数 `k/10000 × 0.05` 比。找到最后一个还满足条件的位置，它前面的全部算显著。

课上问："把阈值从 0.05 放宽到 0.1，差异基因会变多还是变少？误报会变多还是变少？"

（学生答完，顺手把 `alpha = 0.05` 改成 `0.1` 再跑一遍，用眼睛看。比讲十遍有用。）

## 跑之前先猜一下结果

这一步很多老师会跳过，但它其实挺关键。

让学生开跑之前，先猜：差异基因大概几十个、几百个还是几千个？

猜完再跑：

```bash
Rscript scripts/01_diff_analysis.R  .  ./results
```

控制台应该出现：

```
Loaded 10000 genes x 12 samples
Significant DEGs (padj<0.05, |log2FC|>1): 116
  up-regulated: 76 | down-regulated: 40
```

看到"猜 2000 个"的同学对着 116 发愣，这就是个很好的教学时刻——真实数据里，差异基因没有想象中那么多。

数字不对怎么办，按这个顺序查，别跳步：

1. 命令行两个参数对不对（`.` 是当前目录，`./results` 是输出目录）；
2. `sample_meta.csv` 里 `condition` 是不是只有 Normal 和 Tumor 两种值；
3. `all(colnames(counts) == meta$sample_id)` 这一句过没过；
4. 有没有 NA 被筛掉了。

顺便把 EGFR 找出来看一眼。在 `deg_table_all.csv` 里按 `padj` 排序，它排第 2，`log2FoldChange` 约 3.51。

这个"第 2"是**完整差异表按显著性排序**的结果。记住这个口径，第三步还会出现另一个排名，两个不一样，到时候不要混。

## 火山图：能读什么，不能读什么

横轴 `log2FoldChange`，纵轴 `-log10(padj)`。

板块很清楚：右上角是肿瘤里显著升高的，左上角是显著降低的，中间的灰点是不满足门槛的。两条虚线是 `log2FC = ±1`，一条横线是 `padj = 0.05`。

学生第一眼都会看右上角。这时候问一句："纵轴最高的那个点，是表达量最高的基因吗？"

不是。纵轴只代表统计证据的强度，跟表达量的绝对值没关系。一个表达很低的基因，只要组内很稳定，也可能冲到上面去。

再问："这张图能告诉你哪个基因是肿瘤的驱动基因吗？"

不能。它只能告诉你两组的平均值不一样。

应该让学生自己动手写一句"这张图不支持的结论"，比如：

> 右上角的基因一定是致病基因。

这句话写出来，学生自己就发现问题了——图上没有任何信息能支持"致病"两个字。

# 第三学时：从基因列表，到通路，再到候选

## 一百个基因摆在你面前，看不出所以然

116 个基因名，一屏都放不下。盯着看，看不出机制。

富集分析换了个问法：

> 已知的生物学过程有成百上千个。我这个 116 个基因，落在哪些过程里的比例，明显高于随机情况？

这就是 `02_enrichment.R` 干的事。运行：

```bash
Rscript scripts/02_enrichment.R  .  ./results
```

脚本流程：读差异表、筛出显著基因、用 `bitr()` 把基因名转成 Entrez ID、跑 GO 生物学过程富集、再跑 KEGG 通路富集，最后画 dotplot 出表。

KEGG 那步包在 `tryCatch` 里了。因为 KEGG 要联网，机房断网是常态。报错信息长这样：

```
KEGG enrichment failed (network?): ...
```

看到这个别慌，这不是分析错了，是网断了。备选方案是打开 Enrichr 网页（`https://maayanlab.cloud/Enrichr`），上传 `results/deg_symbols.txt`，选 KEGG_2021_Human，一样能出结果。

---

## 背景集：最容易被糊弄过去的一步

富集结果里有两个数经常被念错。

第一个是 Count：我的基因列表里，有多少个落在这一条通路里。

第二个是背景：我从多少基因里挑出了这 116 个。

两个数必须一起看。举例：

- 背景 10000 个基因，通路有 200 个基因，我命中了 12 个；
- 背景 500 个基因，通路有 200 个基因，我命中了 12 个。

第二个情况明显更"厉害"，但很多报告只写"命中 12 个基因"。

背景集应该是什么？是"有机会被检验到的基因"。这份数据里只检测到 10000 个基因，那 10000 就是背景。如果把背景设成"全部人类基因（两万个）"，等于把那些根本没进表的基因也算进去当分母，显著性会被高估。

还有一种错误，学生写报告时特别爱犯：

> 上调基因和下调基因混在一起做富集，然后写"这条通路被激活"。

上调下调方向相反，掺在一起只能说"这条通路里的基因有变化"，不能说激活或抑制。想谈方向，就分开做两次。

---

## 交集：把 116 个缩到 18 个

第三个脚本很短：

```r
candidates <- inner_join(sig, panel, by = "symbol") %>%
  arrange(desc(log2FoldChange)) %>%
  mutate(rank = row_number())
```

把显著差异基因和 `druggable_panel.csv`（247 个已知可成药基因）取交集，按变化幅度从大到小排个序。

```bash
Rscript scripts/03_target_shortlist.R  .  ./results
```

出 `target_shortlist.csv`，实测 18 行，列是 `rank, symbol, panel_class, log2FoldChange, padj, baseMean`。

脚本还会顺手打印 EGFR/MAPK 通路里有哪些基因出现在了差异名单里，这个在讨论环节用得上。

课上追问两个问题：

"从 116 个变成 18 个，砍掉了什么？"

"不在面板里的基因，是不是就一定做不了药？"

第二个问题的答案是否定的。面板只是"目前已知有药在做的靶点清单"，它记录的是历史，不是可能性。真要严格讨论可成药性，得回到课程二那种结构层面的分析。

---

## EGFR 为什么有两个名次

这是今天最值得抠的细节。

- `deg_table_all.csv` 里按 `padj` 排，EGFR 第 2；
- `target_shortlist.csv` 里按 `log2FoldChange` 排，EGFR 第 1。

两张表，两个名次，数据没毛病。

因为排序的**依据**不一样：一个是统计证据，一个是变化幅度。而且第二张表里只有 18 个基因在比，分母都不同。

以后写报告、做汇报，别人问"EGFR 是不是最好的靶点"，标准答案是："在哪张表里、按什么排序？"只甩一句"排第一"，是不完整的。

# 第四学时：让 AI 帮忙写代码，然后自己负责

## 先说规矩

这门课不要求学生会写 R。但也不希望学生只会照着脚本敲。

所以安排了这么一段：让 AI 解释代码、写小段代码、改参数，然后**自己**审查、运行、核对。

规矩得先讲清楚：

可以给 AI 看变量结构（`dim()`、`str()`、`names()` 的输出）、完整报错、少量脱敏示例、公开的代码片段。

不要给 AI 看：完整的数据矩阵、患者信息、账号密钥、内部项目路径。

课上的数据是合成的，不敏感。但习惯要在这里养成，因为以后进了实验室，手里的数据就不一样了。

---

## 练四件事

### 第一件：让 AI 讲一段代码

把这一段贴过去：

```r
meta$condition <- relevel(factor(meta$condition), ref = "Normal")
dds <- DESeqDataSetFromMatrix(countData = counts, colData = meta, design = ~ batch + condition)
dds <- DESeq(dds)
res <- results(dds, contrast = c("condition", "Tumor", "Normal"), alpha = 0.05)
```

提示词：

```
逐行解释下面这段 R 代码在做什么，输入输出分别是什么。
重点说明 relevel 的作用、design 公式里 batch 和 condition 各是什么角色、
contrast 里两个条件的先后顺序对 log2FoldChange 符号的影响。
不要补充我没提供的信息，也不要改写代码。
```

拿到回答以后，对着脚本本身核一遍。AI 如果说"batch 是主要研究对象"，直接把这句划掉——研究对象是 condition。

### 第二件：让 AI 写一段统计

```
我有数据框 res_df，列名是 symbol、log2FoldChange、padj。
写一段 R，统计 padj < 0.05 且 abs(log2FoldChange) > 1 的基因数，
并分别给出上调和下调的数量。要处理 padj 是 NA 的情况。
```

拿回来以后看三处：用的是 `padj` 还是 `pvalue`；NA 是怎么处理的；跑出来的数跟 116 / 76 / 40 对不对得上。

很多时候 AI 会给一版"能跑但数不对"的代码，正好用来说事。

### 第三件：改阈值，考的是同步性

```
把阈值改成 padj < 0.01 且 abs(log2FoldChange) > 1.5。
同时检查：筛选条件、火山图配色、两条竖线、一条横线，哪些地方要跟着改。
把所有需要改的地方列出来。
```

这个任务的坑在于：只改 `filter()` 不改画图那几行，图和数字就对不上了。图上的线还画在 ±1，可你的筛选早就变成 ±1.5 了。

学生自己跑一遍，一眼就能看出来。

### 第四件：读报错

直接把真实的报错扔给 AI：

```
Error in `all(colnames(counts) == meta$sample_id)`: 
```

让它给排查顺序，然后照着查：列名对不对、样本顺序对不对、`read.csv` 有没有写 `row.names = 1`。

---

## 拿回来的代码，怎么审

给学生一张清单，逐条打钩：

- 变量名是我数据里真实存在的列名，不是 AI 编的
- 用的是 `padj`，不是 `pvalue`
- NA 怎么处理写清楚了
- 阈值、配色、参考线三处同步了
- 分组方向没弄反（Tumor / Normal）
- 里面的路径是我自己的，不是 AI 编的绝对路径

然后本地跑，核对（`significance` 那一列不存在于 csv 里，是画图时临时造的，所以直接按条件数）：

```r
res_df <- read.csv("results/deg_table_all.csv")
nrow(res_df)                                                            # 10000
sum(res_df$padj < 0.05 & abs(res_df$log2FoldChange) > 1, na.rm = TRUE)  # 116
sum(res_df$padj < 0.05 & res_df$log2FoldChange > 1,  na.rm = TRUE)      # 76
sum(res_df$padj < 0.05 & res_df$log2FoldChange < -1, na.rm = TRUE)      # 40
```

最后交一份 `ai_code_review.md`，写清楚：我给了 AI 什么、用了什么提示词、它返回了什么、我查出什么问题、跑出来什么结果、我接受或拒绝了哪部分。

一句话：**AI 可以帮你写代码，但报告里的结论只能来自你自己跑出来的数字。**

## 从差异基因到药靶，中间隔着六层

116 个差异基因，只是第一层。想走到"值得做成药"，得补：

**表达差异**——这层今天做完了。

**通路证据**——今天做了一半。能看到增殖相关的过程排在前面，但别把"富集"当成"机制"。

**因果证据**——敲掉这个基因，疾病表型会不会变。需要敲除、敲低、过表达实验。今天完全没有。

**临床证据**——患者队列里，这个基因的表达或突变跟预后、疗效有没有关系。需要 TCGA 这类数据。今天没有。

**可成药证据**——有没有可结合的口袋，或者已有药物。课程二看结构，课程三做设计。

**安全性证据**——正常组织是不是也依赖它。今天最缺的就是这层，也最容易被忽略。

上课的时候让学生把"我们今天完成了哪几层"圈出来，很多人会发现自己高估了。

## EGFR：好在哪，哪里可疑

支持它的理由：

- 表达显著升高，`log2FC` 约 3.51
- 完整表按 `padj` 排第 2
- 18 个可成药候选里排第 1
- 受体酪氨酸激酶，类别清楚
- 所在通路在富集结果里靠前
- 现实中已经有针对它的药，说明这条路临床上走通过

必须同时写的反证：

- mRNA 高，不等于蛋白高，更不等于受体正在被激活
- 高表达可能只是伴随现象，不是驱动
- 真正驱动肺癌的往往是激活突变（L858R、外显子 19 缺失），而这份数据里没有突变信息
- EGFR 在正常上皮里也表达，抑制它会有皮肤和消化道毒性
- 不同患者对 EGFR 抑制剂的反应差得很远，需要分层

讨论时给学生一个"必须从对面挑刺"的任务：两个人一组，一个为 EGFR 辩护，一个专门拆台，最后合写一段结论。

## 结论该怎么写

先看一段不能用的：

> EGFR 表达显著升高，排名第一，是肺癌的关键靶点，可以做药。

问题在哪？把相关写成了因果，"可以"两个字没有任何证据兜底。

再看一段能用的：

> 10000 个基因中，116 个满足 `padj < 0.05` 且 `|log2FC| > 1`（上调 76、下调 40）。18 个与可成药面板重叠的基因里，按 `log2FoldChange` 排序 EGFR 排第 1（`log2FC` 约 3.51），在完整差异表中按 `padj` 排第 2。GO 富集 top 项集中在肽类激素响应与胰岛素受体信号（这批 DEG 多为 EGFR/MAPK/PI3K 下游共享激酶），上皮细胞增殖（`p.adjust` ≈ 3.8e-7）与 positive regulation of ERK1 and ERK2 cascade（≈ 2.7e-5）同样显著。这些结果支持把 EGFR 列入优先验证名单，但不能证明因果：本课数据无突变信息、无蛋白水平、无功能实验，也未评估安全性。下一步需在细胞和患者样本中验证 EGFR 依赖性与蛋白活化状态，并补做结构层面的可成药性分析。

两段话的区别，就四件事：数据是什么、看到了什么、支持什么、还差什么。写报告就照这个骨架填。
